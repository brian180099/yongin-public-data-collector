# 공공데이터포털 용인시 CSV 확장 결과

> **갱신(2026-11-06):** 운영 DB는 다시 **Supabase**로 돌아갔다. 아래 로컬
> PostgreSQL 대량 적재(316개 데이터셋·약 1,264만 행)는 보존용 스냅샷이며 현재
> 웹·n8n 운영 DB가 아니다. 2026-11-06 Supabase 조회 기준 운영 DB에는 등록 자료
> 278개, 현재 레코드 262,912행이 있다. 로컬과 Supabase는 동기화되지 않는다.
> 최신 상태는 [COLLECTOR_STATUS.md](COLLECTOR_STATUS.md)를 기준으로 한다.

기준일: 2026-11-05. 공식 공공데이터포털의 파일데이터에서 `용인`, `용인시`를 각각 검색했다. 검색 결과는 116건과 320건, 중복을 뺀 고유 자료는 384종이다. CSV 표시 자료는 348종이며, 제공기관이 정확히 `경기도 용인시`인 281종을 대상으로 삼았다. 다른 제공기관의 67종은 사용자 선택에 따라 제외했다.

| 확인 항목 | 결과 |
|---|---:|
| 용인시 제공 CSV 표시 자료 | 281개 포털 자료 |
| 공식 파일 원본 확보 | 279개 포털 자료 |
| 다운로드 버튼 없이 외부 링크만 있는 자료 | 2개 (`15136680`, `15136675`) |
| 로컬 DB 현재 레코드가 있는 자료 | 316개 데이터셋, 12,639,604행 |
| 현재 레코드의 서로 다른 공식 포털 URL | 279개 용인시 CSV URL + 기존 별도 출처 1개 |
| 로컬 DB 크기 | 약 13,923 MiB |

한 포털 자료의 ZIP에 CSV 여러 개가 들어 있으므로 포털 자료 수와 DB 데이터셋 수는 같지 않다. 기존 57개 데이터셋과 수집기의 별도 출처 레코드도 전체 DB 건수에 포함된다. 숫자는 `analytics.current_dataset_records`와 `analytics.dataset_sources`를 읽기 전용 계정으로 실제 조회한 값이다. 자료별 원본 수집·검증·적재 상태는 Git 제외 `data/state/`에 보관한다.

기존에 보류됐던 중복 행·식별자·날짜 형식 문제의 포털 자료 9개도 재검증해 로컬 DB에 적재했다. 원본 행의 중복을 제거하지 않고 내용 해시와 출현 순번을 합쳐 운영 레코드의 식별자로 사용했다. 잘못된 날짜는 분석용 날짜로 단정하지 않고 원본 문자열로 보존했다. 일부 파일의 완전히 빈 패딩 행은 개수를 품질 기록에 남기고 운영 레코드에서 제외했다. 이름 없는 헤더는 운영 payload에서만 별도 이름으로 표시했다. 원본 바이트와 SHA-256 증거는 그대로 보존한다.

Supabase Free DB는 이전 적재 상태에서 추가 대량 쓰기를 중단했다. 로컬 DB는 그 상태를 복제한 뒤 새 자료를 적재했으며, 두 DB는 동기화되지 않는다. 웹·n8n 분석은 로컬 읽기 전용 DB를 사용한다. 데이터별 적재는 트랜잭션으로 완료되거나 실패하며 실패 시 기존 정상 레코드를 유지한다. 새 대용량 자료의 정기 자동 갱신은 활성화하지 않았다. 배치 실행·보안 경로는 [로컬 PostgreSQL 운영 문서](LOCAL_POSTGRESQL.md)에 있다.
